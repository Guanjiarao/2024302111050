# Lab4 设计与验收笔记

## 参数与基线

`kernel/course_sid.h` 是个性化参数唯一来源：`COURSE_SID=2024302111050`、`LAB4_POLICY_ID=0`、`LAB2_TICK=3`。票数派生值为 18，仅由 `setickets` 写入 `struct proc.tickets`，两级 MLFQ 不使用票数选进程。`kernel/param.h` 的 `NPROC=64`，能容纳 shell、父进程和官方 bench 的 8 个并发子进程。

## trapframe 与 context

`kernel/proc.h` 中 `struct trapframe` 服务于 U/S 特权级切换，保存用户态 31 个通用寄存器以及 `kernel_satp/kernel_sp/kernel_trap/epc/kernel_hartid`，由 `kernel/trampoline.S` 的 `uservec/userret` 搬运。`struct context` 服务于两个内核执行流之间切换，只按 ABI 保存 callee-saved 的 `ra、sp、s0-s11` 共 14 个寄存器。caller-saved 寄存器已经由调用 `swtch` 的 C 函数按 ABI 负责，故无需重复保存。

`kernel/swtch.S` 的 a0 是旧 context 地址，a1 是新 context 地址；字段偏移从 `ra=0`、`sp=8` 到 `s11=104`，与 `struct context` 顺序一致。它不显式保存 PC，因为调用 `swtch` 时返回地址已经在 `ra`；恢复另一个 context 的 `ra` 后执行 `ret`，就回到该执行流上次调用 `swtch` 的下一条指令。首次调度没有旧返回点，所以 `allocproc()` 把 `context.ra` 初始化为 `forkret`，`context.sp` 指向独立内核栈顶。

## 每进程内核栈与锁交接

`allocproc()` 使用 `kalloc()` 为每个进程分配一页内核栈，物理地址在内核恒等映射中可直接作为 VA；`trap.c:prepare_return()` 把 `trapframe->kernel_sp` 指向 `p->kstack + PGSIZE`。`exit()` 只把进程变为 ZOMBIE 并切走，不释放当前正在使用的栈。父进程在 `proc_wait()` 中确认 ZOMBIE 后调用 `freeproc()`，统一释放用户页表、trapframe 和内核栈。

`p->lock` 必须跨越 `swtch`：进程先持锁把状态从 RUNNING 改成 RUNNABLE/SLEEPING/ZOMBIE，再由 `sched()` 切到 scheduler；scheduler 返回后清空 `c->proc` 并释放该锁。反向切入进程时 scheduler 持锁并设置 RUNNING，旧进程从 `sched()` 返回后在 `yield()`/`sleep()` 中释放；首次运行从 `forkret()` 开始，所以 `forkret()` 第一条逻辑是释放 scheduler 交接来的 `p->lock`。否则 RUNNABLE 进程可能在尚未离开旧内核栈时再次被选中，造成两个执行流共享一栈。

## sched 不变式与调用关系

`kernel/proc.c:sched()` 检查：持有 `p->lock`；`mycpu()->noff==1`，即除该锁外没有别的自旋锁；状态不是 RUNNING；中断关闭。切换前保存 `c->intena`，返回后恢复。

- `scheduler()`：开中断，选择最高优先级 RUNNABLE 进程，同层从 `rr_idx` 后轮转；设置 RUNNING、`c->proc` 和 `last_slice_ticks=0`，再 `swtch(&c->context,&p->context)`。无可运行进程时开中断并 `wfi`。
- `yield()`：获取 `p->lock`，置 RUNNABLE，调用 `sched()`，恢复后释放锁。
- `sleep(chan,lk)`：先取 `p->lock`，再释放条件锁 `lk`，设置 chan/SLEEPING，调用 `sched()`；醒来后清 chan、释放进程锁并重新获取条件锁。
- `wakeup(chan)`：遍历进程，跳过当前进程；持目标 `p->lock` 检查 SLEEPING 和 chan，置 RUNNABLE 并回到高优先级。
- `wait/exit`：`wait_lock` 保护 parent 关系和 ZOMBIE 检查；`wait` 无僵尸但有孩子时 `sleep(parent,&wait_lock)`；`exit` 持 `wait_lock` 唤醒父进程，再持自身锁置 ZOMBIE 并 `sched()`，绝不返回。

## A 用户态到 B 用户态

完整路径是：A 在用户态被时钟打断，`uservec` 将用户寄存器保存到 A 的 trapframe 并切内核页表/内核栈；`usertrap` 统计 tick，达到时间片后调用 `yield`；`yield -> sched -> swtch` 从 A 内核栈切到 CPU scheduler 栈；`scheduler` 返回并选择 B，再 `swtch` 到 B 的内核栈；若 B 运行过则从其 `sched` 返回，否则首次进入 `forkret`；最终 `prepare_return -> userret -> sret` 恢复 B 的 trapframe，回到 B 用户态。

## 自旋锁与中断嵌套

`kernel/spinlock.c` 实现 `initlock/acquire/release/holding/push_off/pop_off`。`noff` 和 `intena` 属于 `struct cpu`。`acquire` 先 `push_off`，原子交换锁并记录持锁 CPU；`release` 清所有者并 `pop_off`。当前验收为 `-smp 1`，结构仍按每 CPU 组织，不使用全局静态的中断嵌套状态。

## lost wakeup 与锁序

错误交错：A 持条件锁检查“无数据”，先释放条件锁；B 获取条件锁、生产数据并调用 `wakeup`，此时 A 尚未标记 SLEEPING，唤醒落空；A 随后标记 SLEEPING 并永久阻塞。正确实现中 A 先获取自身 `p->lock`，再释放条件锁；B 的 `wakeup` 必须获取同一把 `p->lock` 才能检查/修改状态，所以“条件检查结束到进入 SLEEPING”的窗口被互斥覆盖。

涉及父子关系时锁顺序固定为 `wait_lock -> child/self p->lock`。`wait()` 扫描孩子时持 `wait_lock` 再短暂持 child lock；`exit()` 持 `wait_lock` 完成 reparent/wakeup，再持自身锁置 ZOMBIE。进入 `sched()` 前必须已释放 `wait_lock`，只留下自身 `p->lock`。

## 两级 MLFQ

新进程和唤醒进程进入高优先级。`scheduler()` 始终先选高优先级，并以 `rr_idx` 保证同层公平。`usertrap()` 仅统计从用户态进入的时钟中断：`cpu_ticks++`、`last_slice_ticks++`。高层累计到 3 tick 时降到低层并 `yield`；低层累计到 6 tick 时保持低层并 `yield`。在时间片耗尽前主动 `pause` 或因 console/wait 阻塞，`sleep()` 将其恢复为高优先级。没有启用周期 priority boost；交互进程的主动阻塞提升与同层轮转已经满足本实验的防饥饿观测要求。

## pause 与观测系统调用

`trap.c:clockintr()` 持 `tickslock` 增加全局 `ticks` 并 `wakeup(&ticks)`；`proc_pause()` 持同一锁检查经过时间，条件不足时调用 `sleep(&ticks,&tickslock)`，因此检查与睡眠不存在丢失唤醒窗口。负数返回 -1。

`sys_schedstat` 调用 `proc_schedstat()`，在目标 `p->lock` 内读取两个整数，释放锁后才对调用者页表执行 `copyout`；无效、ZOMBIE 或用户地址错误返回 -1。`time_rdtime` 直接返回 `r_time()`，单位为硬件 time CSR。`setickets` 拒绝小于 1 的值，成功时持当前进程锁记录。

## 状态迁移

```text
UNUSED --allocproc--> USED --fork/procinit--> RUNNABLE
RUNNABLE --scheduler(p->lock)--> RUNNING
RUNNING --yield/时间片耗尽--> RUNNABLE
RUNNING --sleep(chan,lk)--> SLEEPING --wakeup(chan)--> RUNNABLE
RUNNING --exit--> ZOMBIE --wait/freeproc--> UNUSED
```

所有状态写入均在对应 `p->lock` 下；parent/ZOMBIE 协作同时受 `wait_lock` 约束。
