# Lab3 设计与验收笔记

本笔记对应 `lab3-v2-20260929` 和说明书 V3.1。实验将 Lab2 的平坦内存模型替换为独立 SV39 用户页表：内核仍恒等映射 RAM 和驱动所需 MMIO；每个用户进程有独立页表和物理页；系统调用通过 `copyin/copyout/copyinstr` 受控访问用户内存。当前实现刻意保留了教学内核的固定 4 项进程表和单核模型，不是完整 xv6。

## 1. 地址空间和页权限

用户虚拟地址从低到高为：

```text
0x0000_0000  用户代码 + 只读数据          R-X-U
             数据起点按 4 KiB 对齐
             用户数据 + BSS               RW--U
             guard page                   不映射
             一页用户栈                   RW--U
             sbrk 堆                       RW--U，按需增长
             未使用区域
TRAPFRAME     进程陷阱帧                   内核 R/W，非 U
TRAMPOLINE    uservec/userret 跳板         S 态 R/X，非 U
```

`user/user.ld` 是课程预置文件，不直接修改。Makefile 从它生成 `user-flat/user.ld`，在 `.data` 前插入 4 KiB 对齐，并定义 `__user_text_end`、`__user_data_start`；链接后的 ELF 符号值写入 `_uprog_table`。加载器据此将代码/只读数据映射为 R-X-U，将数据/BSS 映射为 RW--U。平面二进制不携带 ELF 段权限，因此构建期提取符号并随嵌入程序表传递给内核。

守卫页不分配物理页、不建立 PTE。用户访问它会产生 instruction/load/store page fault（`scause` 12/13/15）；`usertrap()` 对未知用户异常结束当前进程，随后恢复父 Shell，而不是让内核崩溃。用户代码页不含 W 位，写地址 0 的官方测试即使落在已映射代码页，也必须因权限错误而被终止。

## 2. 页分配与内存配额

`kinit()` 从链接脚本导出的 `kernel_end` 向上按页对齐，管理 `[PGROUNDUP(kernel_end), PHYSTOP)`。`LAB3_MEMCAP_DELTA=10`，因此可分配上限是该区间页数减 10 页；其余 RAM 仍在内核恒等映射中，但不交给 `kalloc()`。分配失败统一返回空指针，调用者将其转成 `-1` 并回滚。

分配器用静态位图记录每个 4 KiB 页的空闲/占用状态。128 MiB 对应 32768 个物理页，位图约 4 KiB，位于内核 BSS，不占用受管页。释放通过页索引直接清位，避免有序空闲链表在批量释放时产生 O(n²) 插入成本。`LAB3_ALLOC_ORDER=2` 使用中点向外的确定顺序和游标；分配成功后清零页面，释放前填充 `0x01`，分别用于数据隔离和暴露悬挂引用。

分配器是单核、无锁实现。位图让释放为 O(1)；游标使按配置顺序的连续分配无需每次从头扫描。若未来增加多核，必须加锁并增加跨核 TLB shootdown，不能直接复用当前并发假设。

## 3. 页表 API 和失败回滚

- `walk(pt, va, alloc)` 返回第三级叶 PTE 地址；`alloc=0` 时缺中间级返回空，`alloc=1` 时按需分配零页作为中间页表。非叶 PTE 只有 V 位，叶 PTE 才有 R/W/X。
- `mappages()` 要求 VA/PA 页对齐、拒绝覆盖有效映射。映射失败时清除本次已写入的叶 PTE，并剪除因此变空的中间页表，再刷新本核 TLB。
- **物理页所有权约定：** `mappages()` 只建立 PTE，不取得调用方数据页的释放责任；失败也不释放传入 PA。`uvmalloc()`、`uvmcopy()` 等调用方负责释放未映射成功的当前页，并通过 `uvmunmap()`/`uvmfree()` 释放本次已建立映射所拥有的用户页。中间页表始终由页表 API 创建和回收。
- `uvmunmap()` 先将叶 PTE 置零，再释放可选的数据页；它只对 guard 等缺失映射跳过，不将缺页误认为整次地址空间复制失败。页表变更后执行 `sfence.vma`。
- 新地址空间建立失败时，调用方拆除所有已建立用户映射、释放其中间页表和陷阱帧。`exec` 只有在新页表、镜像、栈和特殊映射全部成功后才交换进程字段并销毁旧地址空间；因此失败保留原进程可运行。

本实验只有 hart 0。`sfence.vma` 在 satp 切换前后、PTE 建立/撤销后执行，防止本核使用旧翻译。多核时这条指令只刷新当前 hart，其他 hart 还需通过 IPI 等机制执行 TLB shootdown。

## 4. 内核页表和跳板

`kvmmake()` 恒等映射 `[KERNBASE, PHYSTOP)`，其中同时包含内核镜像、页分配器管理区、页表页和用户物理页；还恒等映射 UART 页及 PLIC 的 4 MiB MMIO 窗口。CLINT 不映射：定时器走 `time/stimecmp` CSR，不直接访问 CLINT MMIO。预置链接脚本没有 `etext`，所以内核 RAM 阶段性采用 RWX 映射，这不是用户页权限策略。

跳板页在内核页表和每个用户页表都映射到同一 `TRAMPOLINE` 虚拟地址。用户陷入时，PC 仍位于该页，`uservec` 保存现场、切换到内核 `satp` 后进入内核 C 代码；返回时 C 代码用 `TRAMPOLINE + (userret - trampoline)` 跳入同一页，汇编切到用户 `satp`、恢复现场并 `sret`。本版本只有一个固定启动内核栈，不建立 `KSTACK(p)` 的每进程高地址映射；该取舍不改变 Lab0 用户地址空间快照，但与完整 xv6 的内核栈布局不同。

## 5. 受控拷贝和 sbrk

`copyin/copyout` 按页分块：每次用 `walkaddr()` 检查 VA 在 SV39 用户范围内、PTE 有效、带 PTE_U，且分别具备读/写权限；再只复制当前页剩余长度，跨页继续验证。`copyinstr()` 逐字节经 `copyin()` 读取，遇到 NUL 成功、越界或长度耗尽返回错误。逐页块拷贝避免逐字节翻译的大量开销，同时不跨越未经验证的页边界；不能用普通 `memcpy` 直接处理不可信用户指针。

所有已有用户指针入口都采用这些接口：`sys_write` 的缓冲区走 `copyin`，控制台 `read` 的输出走 `copyout`，`exec` 的程序名走 `copyinstr`，`wait` 的退出状态走 `copyout`。Lab2 中直接解引用用户地址的做法已移除。

`SYS_sbrk` 调用号为 12，只执行 EAGER 策略。正数扩展先逐页分配并映射 RW--U；中途失败释放本次已分配页且不更新 `p->sz`，返回 `-1`。负数收缩不得越过初始堆边界，先撤销页映射再更新边界；零返回当前 break。用户访问 break 以上未映射地址会走 page fault 并结束该进程。LAZY 缺页分配留给 Lab5。

## 6. fork、exec 和资源生命周期

`struct proc` 新增 `pagetable`、页对齐分配的 `trapframe`、`sz`、`heap_base`、`guard_va`、`stack_base` 和等待状态字段。`procinit()` 创建 PID 1 和初始 Shell；`proc_exec()` 原子式地建立并交换新地址空间；`proc_fork()` 为子进程创建新根页表和陷阱帧，逐页复制 `[0, sz)` 的 U 页并保留原权限，遇到未映射 guard 页直接跳过；退出路径销毁用户映射、页表层级及独立陷阱帧；`wait()` 在父进程自己的页表内写回退出码后回收进程槽。

为满足 Lab3 回归中 `spin` 与 Shell 并发的检查，增加固定 4 项进程表上的单核轮转调度。每经过 `LAB2_TICK` 个硬件定时器 tick，用户态 trap 已保存完整 trapframe 后，`proc_yield()` 将当前进程置为 RUNNABLE 并挑选下一进程，经 `userenter/userret/sret` 恢复它的用户现场。未完成的 `wait()` 将父进程置为 SLEEPING，子进程退出时写回状态并唤醒父进程。控制台 `read` 无输入且存在其他 RUNNABLE 进程时，`proc_yield_read()` 将 trapframe 的 `epc` 退回本次 `ecall`，让该系统调用在未来重新执行；这使后台 Shell 的阻塞输入不会独占唯一内核栈。Shell 接受 `spin &` 以启动后台任务。

调度仅在用户态陷阱边界进行，不保存/切换被打断的内核 C 调用栈；`read` 通过重新执行用户 `ecall` 来等待，其他内核操作不会在内核态被抢占。所有 hart 共享唯一启动栈，因此 QEMU 必须单核；这是教学用最小调度器，不是通用 SMP 调度器。

## 7. 页表 dump 和验收用例

首个 Shell 页表装配完成后自动打印一次 dump；`dumppt` 命令通过教学扩展系统调用重放当前进程页表。遍历顺序按 VPN 索引递增，因此 VA 升序。非叶行格式为 `L2/L1 va=0x... pa=0x... perm=----`；叶行按 R/W/X/U 顺序输出四字符权限，A/D 位不输出。

建议验收演示顺序：

1. 启动 QEMU，检查 Banner、初始 dump 和 `sh> `。
2. 输入 `spin &`，随后输入 `hi`；观察 `spin N` 与 Shell 命令输出交错，说明用户态定时器 trap 的轮转路径。
3. 输入 `dumppt`，指出低地址代码的 `r-xu`、数据/栈/堆的 `rw-u`、guard 缺项、trapframe 的 `rw--` 和 trampoline 的 `r-x-`。
4. 输入 `badaccess`，检查 `TEST-3a PASS` 与 `TEST-3b PASS`，说明用户异常只结束子进程。
5. 输入 `guardtest`，检查 `GUARD PASS`；输入 `copyedge`，检查跨页字节完整输出及 `COPYEDGE PASS`。
6. 输入 `memcap`，等待它耗尽配额并检查 `TEST-4 PASS`，确认 OOM 返回错误且内核未 panic。

编码自测记录在 `tests/lab3.script`：`guardtest` 从 `end` 符号计算实际 guard VA 后写入；`copyedge` 用跨页缓冲调用 `write` 验证 `copyin` 的跨页处理。官方 `badaccess` 和 `memcap` 源码及判定标准保留在 `lab3-v2-20260929/support/tests/`，自动化脚本依次执行它们。

## 8. 思考题要点

- SV39 TLB 未命中且无页表缓存命中时，硬件页表遍历最多需要读取三级 PTE，即三次内存访问；TLB 缓存常用翻译，减少后续遍历。
- 撤销映射应先使 PTE 无效，避免新的遍历继续获得旧映射；本实验单核且正在内核页表执行用户地址空间销毁，`sfence.vma` 在撤销批次后执行。多核需要同步其他 hart 的 TLB 后才能安全复用页面。
- 普通 `memcpy` 不检查用户地址映射与 PTE_U/读写权限。恶意进程可让内核越界读写、读到其他进程/内核数据或破坏内核状态；`copyin/out` 在每一页执行权限检查并将错误作为普通失败返回。
