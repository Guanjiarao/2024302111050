## 四、代码讲解顺序

老师要求定位代码时，按以下顺序打开：

1. `kernel/entry.S`：关中断、读取 hartid、4 KB 栈、`mtvec`、调用 `start`。

## 五、Lab1 高频问答

### 1. QEMU 复位后第一条指令在哪里？为什么内核链接到 0x80000000？

第一条指令位于 `0x1000` 的 QEMU Boot ROM。`-bios none` 表示不加载 OpenSBI 等外部固件，但 QEMU 仍提供最小复位跳板，把 CPU 跳到 `-kernel` 加载的入口。QEMU virt 的 RAM 从 `0x80000000` 开始，低地址主要是 MMIO，所以内核链接和加载到 `0x80000000`。

### 2. 为什么 `_entry` 一开始关闭中断？

此时栈和陷阱向量尚未准备好。如果中断发生，处理程序无法安全保存现场或调用 C 函数，可能跳到错误地址。因此先关闭 `mie`，建立栈和对齐的 `mtvec` 后再继续。

### 3. 为什么只让 hart 0 运行？

Lab1 是单核启动基线。多个 hart 同时使用同一启动栈和 UART 会破坏栈内容并让输出交错。从核读取 `mhartid` 后进入 `wfi` 停驻循环。

### 4. 栈为什么放在高地址端？为什么是 4 KB？

RISC-V 栈向低地址增长，所以 `sp` 指向预留区末端。预留区和 `sp` 都按 16 字节对齐，满足 ABI。真实学号 `%3=0`，公式是 `4*(1+0)=4 KB`，代码引用 `LAB1_STACK_KB`，没有硬编码个人结果。

### 5. `mtvec` 为什么要求 4 字节对齐？

`mtvec` 的低两位用于保存陷阱模式，基地址必须满足至少 4 字节对齐。代码在 `early_trap` 前使用 `.balign 4`。

### 6. `mret` 前做了什么？

清除 `mstatus.MIE`，把 `mstatus.MPP` 设置为 S 态；把 `mepc` 设置为 `main`；设置 `satp=0` 使用 Bare 模式；配置异常与中断委托但保持中断关闭；最后配置 PMP，执行 `mret`。

### 7. 如果删除 PMP 两行会怎样？

新版本 QEMU 中，S 态默认没有访问物理内存的权限。`mret` 后取 `main` 第一条指令就会发生 Instruction Access Fault，屏幕没有输出，`-d int` 日志通常出现同步异常 `cause=1`。

### 8. 为什么 Lab1 使用 `satp=0`？

Lab1 尚未实现页表，Bare 模式让 S 态地址直接作为物理地址使用。这样可以先独立验证启动、权限切换和 UART；分页在后续实验引入。

### 9. UART 输出用了哪些寄存器？

基地址为 `0x10000000`。偏移 5 是 LSR，bit 5（`0x20`，THRE）表示发送保持寄存器空闲；偏移 0 是 THR。必须等 bit 5 为 1 后再写字符，否则连续输出时可能覆盖尚未发送的数据。

### 10. 为什么 `printf` 不直接访问 UART？

分层职责不同：`printf` 只解析格式并生成字符流，`consputc` 负责协议统计和节流，`uartputc_sync` 负责硬件轮询。这样格式逻辑可以独立测试，硬件细节不会扩散。

### 11. `%d` 如何处理最小负整数？

不能直接对 `INT_MIN` 取负，因为正数范围少一位，会产生溢出。实现先计算 `-(value+1)`，再加 1 转成无符号幅值，随后逐位输出。

### 12. `%x` 的格式要求是什么？

固定输出小写 `0x` 前缀，数字使用 `0-9a-f`，不输出前导零。零输出为 `0x0`。

### 13. 你的 Banner 协议是什么？

协议 0，因为 `2024302111050 % 3 = 0`。输出一行明文，包含十进制学号和 `学号%97` 的小写十六进制值，以换行结束，不附加点号或校验和。

### 14. 你的节流间隔是多少？

公式是 `16 + 学号%16`。本学号 `%16=10`，所以每 26 字节执行一次个性化 `nop` 延迟。代码保留公式并引用 `COURSE_SID`，没有硬编码 26。

### 15. 为什么最后是无限 `wfi`？

Lab1 没有调度器、进程和关机接口。输出完成后用 `wfi` 让 CPU 等待事件，比空忙循环更合理；用户通过 QEMU 的 `Ctrl-a`、`x` 退出模拟器。

## 六、Lab0 抽查问答

### 1. `echo hi` 的总体调用链是什么？

UART 中断接收字符，`uartintr -> consoleintr` 写控制台缓冲；回车更新写指针并唤醒等待输入的 Shell。Shell 解析命令后 `fork`，子进程 `exec` 装载 echo，echo 通过 `write` 输出，随后 `exit` 成为 ZOMBIE，父 Shell 的 `wait` 回收它并打印下一个提示符。

### 2. Shell 等输入时是在轮询吗？

不是。`consoleread` 在缓冲区为空时登记等待通道并进入 `SLEEPING`，回车到达后中断处理调用 `wakeup`，状态恢复为 `RUNNABLE`。

### 3. `fork` 如何让父子进程看到不同返回值？

内核复制父进程 trapframe，然后把子进程 trapframe 的 `a0` 改成 0；父进程的系统调用返回值由系统调用分发路径写成子 PID。返回用户态时，双方从各自 trapframe 恢复 `a0`。

### 4. `exec` 为什么成功后不返回原程序？

`exec` 新建页表、加载 ELF 段和参数栈，最后原子替换进程地址空间，把 trapframe 的 `epc` 改为 ELF 入口、`sp` 改为新栈。系统调用返回时已经进入新程序；只有失败才返回旧程序。

### 5. trampoline 为什么同时映射在用户页表和内核页表？

陷入过程中必须在执行代码的同时切换页表。如果切换后同一虚拟地址不再映射，CPU 无法继续取下一条指令。两个页表把 trampoline 映射到相同虚拟地址和同一物理页，使切换前后指令流连续。

### 6. 时钟中断如何触发上下文切换？

时钟中断进入 trap 路径，`devintr` 识别定时器并更新 ticks；有当前进程时调用 `yield`，将其状态设为 `RUNNABLE`，`sched/swtch` 保存进程 context 并恢复 CPU 调度器 context，调度器再选择下一个 RUNNABLE 进程。
